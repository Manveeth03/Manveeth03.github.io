01

Real-Time Problem & Objectives

Problem statement: different departments within an organization share the same physical network infrastructure, exposing sensitive resources across departmental boundaries. On a flat network every host lives in the same broadcast domain, so a device in Sales can, at the network layer, reach a payroll server in Finance — a direct violation of least privilege.

Objectives

  • Isolate departmental traffic (HR, Finance, IT, Sales) into separate broadcast domains.
  • Allow controlled, explicitly-permitted access to shared resources (e.g. a common CRM or file server).
  • Detect and prevent lateral movement attempts between departments using layered Layer-2/Layer-3 controls.
  • Demonstrate and verify the design practically in Cisco Packet Tracer.
02

Background & Literature Study

A Virtual LAN (VLAN) is a logical subdivision of a switched network that groups devices into separate broadcast domains regardless of physical location, defined by the IEEE 802.1Q standard for frame tagging across trunk links.

Working principle

  • Switch ports are either access (one VLAN, end devices) or trunk (multiple VLANs, tagged with 802.1Q between switches).
  • Devices in different VLANs cannot talk at Layer 2 at all — a Layer-3 device (router or multilayer switch) with an SVI per VLAN is required for inter-VLAN routing.

Security architecture

  • Layer-2 VLAN segmentation by department/function.
  • Layer-3 inter-VLAN routing with ACLs on each SVI.
  • A dedicated unused native VLAN on trunks to prevent double-tagging VLAN hopping.
  • A separate management VLAN restricted to IT/admin.

Security controls, advantages & limitations

ControlPurpose
Port SecurityRestricts MAC addresses per access port; violation → err-disable
DHCP SnoopingBlocks rogue DHCP servers; trusts only uplink ports
Dynamic ARP InspectionValidates ARP against the DHCP snooping binding table
Router / VLAN ACLsEnforces which VLANs may reach which, and over what ports
802.1XAuthenticates devices before granting dynamic VLAN access
Native VLAN hardeningMoves native VLAN off VLAN 1 to block hopping attacks

Advantages: smaller broadcast domains, logical isolation without new cabling, granular auditable control, simple adds/moves/changes, compliance support.
Limitations: VLANs don't encrypt or authenticate traffic; misconfigured trunks/native VLANs remain hoppable; doesn't isolate hosts within the same VLAN; the core router/switch becomes the single most critical control point.

Latest developments & industrial applications

SDN and Cisco ACI/DNA Center now orchestrate VLAN-equivalent segmentation centrally; VXLAN extends the same concept across Layer-3 and cloud fabrics; Zero Trust micro-segmentation increasingly supplements VLANs with identity-aware policy. Industrially, this pattern underlies enterprise campuses, data centers, manufacturing OT/IT separation, and healthcare device isolation.

04

Proposed Security Solution

Three switches (S1, S2, S3) interconnected by 802.1Q trunk links, with three VLANs stretched across all three switches. Each VLAN forms its own broadcast domain regardless of which switch a device is physically connected to, and — since no Layer-3 device or inter-VLAN routing has been configured — VLANs are fully isolated from one another by default.

VLANSubnetDevicesSwitch Ports
10172.17.10.0/24PC1 (172.17.10.21), PC4 (172.17.10.24)S2 F0/11, S3 F0/11
20172.17.20.0/24PC2 (172.17.20.22), PC5 (172.17.20.25)S2 F0/18, S3 F0/18
30172.17.30.0/24PC3 (172.17.30.23), PC6 (172.17.30.26)S2 F0/6, S3 F0/6

Inter-switch trunks: S1 G0/1 ↔ S2 G0/1, S1 G0/2 ↔ S3 G0/2 — both carrying all three VLANs tagged via 802.1Q.

Security mechanism — how this solves the problem

  • Isolation: each VLAN is its own broadcast domain — PCs in different VLANs cannot reach each other at all, since no Layer-3 path exists between them.
  • Trunking: 802.1Q trunks between S1↔S2 and S1↔S3 carry all three VLANs' tagged traffic, so same-VLAN devices communicate correctly even from different switches.
  • Verified behaviour: pings within the same VLAN succeed (e.g. PC1 ↔ PC4 on VLAN 10); pings across VLANs fail because inter-VLAN routing has not been configured — this is the isolation working as intended, not a fault.

Tool selection: Cisco Packet Tracer — used to configure VLANs, access ports, and 802.1Q trunks with realistic IOS-style CLI, and to verify connectivity using ping between devices.

Planned future enhancements

Inter-VLAN Routing (SVIs/router-on-a-stick) · Access Control Lists (ACLs) · Port Security · DHCP Snooping · Dynamic ARP Inspection

05

Practical Demonstration

Topology: 3 switches (S1, S2, S3) + 6 PCs — 2 per VLAN, one on S2 and one on S3, per Fig. 1.

  1. Cable the topology: S2 and S3 each connect to S1, plus 3 PCs each (F0/11, F0/18, F0/6).
  2. Create VLANs 10, 20, 30 on S1, S2, and S3.
  3. On S2 and S3, assign access ports: switchport mode access → switchport access vlan <id> (F0/11→VLAN 10, F0/18→VLAN 20, F0/6→VLAN 30).
  4. Configure the S1–S2 (G0/1) and S1–S3 (G0/2) uplinks as trunks: switchport mode trunk.
  5. Assign each PC a static IP in its VLAN's subnet (e.g. PC1 = 172.17.10.21 /24, PC4 = 172.17.10.24 /24).
  6. Verify same-VLAN connectivity: PC1 → ping 172.17.10.24, PC2 → ping 172.17.20.25, PC3 → ping 172.17.30.26 — all succeed.
  7. Verify isolation: PC1 → ping 172.17.20.22, PC1 → ping 172.17.30.23 — both fail, since no inter-VLAN routing is configured.

Real-Time Application

  • Enterprise networks — separating HR/Finance/IT/Sales exactly as modeled here.
  • Banking & financial services — isolating core banking/payment systems from general corporate traffic.
  • Healthcare — separating clinical/medical-device networks from admin and guest Wi-Fi.
  • Data centers — VLANs/VXLAN isolating tenant workloads or application tiers.
  • Educational institutions — separating student, faculty, and administrative networks.
  • SOCs — monitoring inter-VLAN traffic at the core as a natural logging chokepoint.
  • Manufacturing — isolating OT/ICS from corporate IT to protect production systems.

SDG Mapping — SDG 9

Industry, Innovation and Infrastructure: a flat, unsegmented network is fragile infrastructure — one compromised device can jeopardize an entire organization's digital systems, undermining SDG 9's call for resilient infrastructure.

  • Supports secure enterprise networks by design, giving organizations resilient infrastructure to build on.
  • Reduces the blast radius of incidents, protecting continuity of business/industrial operations.
  • Uses a standards-based (IEEE 802.1Q), scalable design aligned with sustainable industrialization.

Impact: societal (protects employee PII), industrial (enables confident digital adoption across banking/healthcare/manufacturing), technological (a reusable pattern scaling to SDN/VXLAN deployments).

Key Learning Outcomes & Conclusion

  • Understood how flat networks create lateral-movement risk and why segmentation is foundational.
  • Learned to design and configure VLANs, trunking, and inter-VLAN routing in Cisco IOS via Packet Tracer.
  • Applied layered controls (port security, DHCP snooping, DAI, ACLs) to enforce policy in practice.

VLAN segmentation directly addresses departments sharing sensitive resources over one flat network. Combining Layer-2 isolation with Layer-3 ACL enforcement and supporting controls ensures departmental traffic stays isolated by default, while still allowing controlled, auditable access to shared resources — a pattern that scales from a single campus to full SDN/VXLAN deployments.
